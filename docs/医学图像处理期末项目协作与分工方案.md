# 医学图像处理期末项目协作与分工方案

**项目：** 任务四 Brain Stroke CT Dataset 脑卒中 CT 图像分割  
**仓库：** https://github.com/echo14670/brain-stroke-ct-segmentation  

本方案采用简化实验设计：团队只维护一套训练、推理和评估代码。1名成员负责跑通简单 2D U-Net 基线，另外 4 名成员分别完成数据掩码、预训练编码器、损失函数和输入分辨率四个单变量实验。组长负责项目管理与汇报，PPT 负责人负责汇报材料。

## 一、GitHub 协作规范

### 1.1 权限与基本原则

- `main` 始终保持可运行，任何人不得直接在 `main` 上提交实验代码。
- 所有工作先建立 Issue，再从 `main` 创建短期分支。
- 一个分支只完成一个 Issue，一个 Pull Request 只解决一个明确问题。
- 团队只维护一套训练、推理和评估入口，不同实验通过配置文件和独立模块切换。
- `External_Test` 只用于最终评估，不参与训练、调参或阈值选择。
- 每次实验必须固定数据切分、随机种子、配置和评估脚本。

### 1.5 基线冻结与实验顺序

团队已确认当前版本作为正式基线 `baseline-v1`。它是后续全部实验唯一、固定的控制组，定义如下：

- 简单 2D U-Net
- 256×256 单通道灰度输入
- 基础红色 OVERLAY 掩码
- Normal 样本使用全零掩码
- 无数据增强
- `Dice+BCE`
- 从零训练
- 固定 `main_split.json` 和随机种子 42
- 统一评估脚本和固定阈值 0.5

基线冻结与并行实验顺序如下：

1. 数据负责人确认当前 `main_split.json` 的病例成员关系后，将其冻结为 `baseline-v1` 切分；冻结后不得增删病例。
2. 基线负责人提交当前 GPU 训练得到的配置、权重、日志、曲线、指标和逐病例结果。
3. 基线成功后创建固定标签：

```bash
git tag baseline-v1
git push origin baseline-v1
```

4. `baseline-v1` 创建后，E1、E2、E3、E4 四个分支从该标签并行开始。
5. E1 只负责数据质量修正：比较基础红色掩码与红蓝并集掩码，处理异常尺寸、空掩码和标签不一致；E1 不从基线中删除任何样本。
6. E2、E3、E4 分别只改变预训练编码器、损失函数和输入分辨率，继续使用 `baseline-v1` 的基础红色掩码、固定切分和无增强设置。
7. E1 的结果只用于判断最终组合是否采用数据质量修正，不得回头修改或覆盖 `baseline-v1` 的指标。
8. 四个实验完成后，只选择表现最好的两个方向做最终组合，不直接叠加全部改动。
9. 最终提交前创建：

```bash
git tag v1.0-course-submission
git push origin v1.0-course-submission
```

如果数据负责人在审计中发现必须改变切分病例成员关系的严重问题，应创建新的切分版本并重新运行基线；不得在未记录的情况下修改 `baseline-v1` 的病例集合。

### 1.6 Pull Request 流程

开始实验前执行：

```bash
git fetch origin
git switch main
git pull --ff-only
git switch -c exp/resnet34
```

完成实验后提交：

```bash
git add configs/experiments/E2_resnet34.yaml
git add reports/experiments/E2_resnet34/
git commit -m "exp(model): evaluate pretrained ResNet34 encoder"
git push -u origin exp/resnet34
```

然后在 GitHub 创建 Pull Request。PR 必须包含：

```text
关联 Issue
修改了哪些文件
训练与评估命令
使用的数据切分和随机种子
阳性病例 Dice、IoU、Precision、Recall
Normal 假阳性指标
External_Test 结果
结论：达到还是未达到改进目标
```

评审规则：

- 每名实验负责人不能批准自己的 PR。
- 你负责检查代码接口、数据切分、模型调用和指标脚本。
- 组长负责检查 Issue 范围、交付完整性和最终合并。
- 涉及训练入口或评估脚本的 PR，由你先评审。
- 组长确认后使用 Squash Merge。
- 合并后删除任务分支，并在 Issue 中记录最终结论。

### 1.7 实验记录与结果目录

每个实验必须保存到：

```text
reports/experiments/<实验编号>/
```

至少包含：

- `config.yaml`：最终实验配置
- `metrics.json`：统一评估结果
- `summary.md`：实验目的、对照结果、结论和是否建议采用
- `run.log`：训练和评估日志
- `curves.png`：损失或 Dice 曲线，可选
- `samples.png`：典型成功与失败样例，可选

`summary.md` 必须写明：

- 基线指标
- 本实验指标
- 指标变化
- 是否达到预期
- 主要失败案例
- 是否建议进入最终组合

### 1.8 数据、模型与大型文件

- 不得重复提交整份 CT 数据集。
- `runs/`、`outputs/`、`checkpoints/`、`tmp/`、`.ipynb_checkpoints/` 和数据集缓存默认不提交。
- `.pth`、`.ckpt` 等模型权重不直接提交到 Git。
- 课程提交所需的模型权重通过 GitHub Release、团队共享盘或最终压缩包交付。
- Notebook 仅用于探索和展示，可复用代码必须整理到 `src/` 或 `scripts/`。
- 最终提交包由组长统一整理，PPT 和数据只引用已合并到仓库的结果。

### 1.9 同步与完成标准

团队汇报前进行一次正式同步，其余时间在 Issue 中异步更新。每位成员汇报三项内容：

1. 已完成内容
2. 下一步计划
3. 当前阻塞项

任务完成必须同时满足：

- 代码或文档已经评审并合并
- 相关配置和实验记录已提交
- 最小运行命令通过
- 指标由统一评估脚本生成
- Issue 已更新并关闭

### 2.3 统一评估与进展标准

所有实验必须使用相同的 `main_split.json` 和 `scripts/evaluate.py`。建议统一报告以下指标：

- 阳性病例平均 Dice
- 阳性病例平均 IoU
- Precision
- Recall
- Normal 图像假阳性像素比例
- Bleeding 与 Ischemia 分组指标
- External_Test 图像级卒中检出 F1
- 参数量、训练时间和单张推理时间

一个方向可以认为取得进展，至少满足以下一项：

- 阳性病例 Dice 相对基线提高约 0.02，且 External_Test 不明显下降。
- Dice 基本不变，但 Recall 或小病灶检出明显提高。
- 分割指标基本不变，但 Normal 假阳性明显下降。
- 指标接近，但训练或推理效率有明显改善。

筛选阶段每个实验先使用一个固定随机种子。表现最好的两个方向再使用第二个随机种子复跑确认。最终最多组合两个方向，并由你负责完成组合实验。

### 2.4 文件责任边界

为避免冲突，以下文件只允许指定负责人修改：

- `data/splits/main_split.json`：只由数据负责人创建和冻结，其余成员只读。
- `scripts/train.py`：只由你修改，其他成员通过配置调用。
- `scripts/evaluate.py`：只由你修改，所有实验必须使用同一脚本。
- `src/data/`：主要由数据负责人修改，涉及核心接口时由你评审。
- `src/losses/`：只由损失函数负责人修改。
- `configs/experiments/`：每位实验负责人只能修改自己的配置文件。
- `docs/`：PPT 负责人和组长负责，其他成员只提交必要素材。
- 模型权重、预测输出和训练缓存不进入 Git。

### 2.5 最终组合与提交

四个独立实验完成后，由你、组长和相关实验负责人共同选择表现最好的两个方向，在 `release/final` 分支合并。只有完成验证的组合配置才能进入最终报告和 PPT。

最终提交前核验：

1. `main` 可运行正式基线推理。
2. `baseline-v1` 与正式基线指标一致。
3. 四个实验均有 Issue、分支、PR 和完整结果目录。
4. 最终组合实验使用冻结切分和统一评估脚本。
5. PPT 和报告中的数字均可追溯到 `reports/experiments/`。
6. 模型权重和压缩包已放入约定的提交位置。
7. 组长完成 `v1.0-course-submission` 标签和最终材料检查。
